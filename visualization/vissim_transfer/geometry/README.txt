AMBUGO MOHALI GEOMETRY TRANSFER — PREPARATION ONLY

Main file: Mohali_AmbuGo_Geometry.xodr
Format: OpenDRIVE1.4, generated by SUMO netconvert1.28.0.
This is candidate geometry for native PTV Vissim import. Vissim has NOT imported
or simulated it on this host. No INPX project has been fabricated.

The file contains all479 original directed regular roads and556 regular lanes,
plus805 junction-connecting roads and220 OpenDRIVE junction elements. Every source
road ID is mapped in sumo_to_opendrive_road_ids.json. The six physical Fortis
roundabout arcs are retained. This is the exact corrected source network used
for the earlier synthetic-traffic demonstration, not measured lane-level data.

The default SUMO compatibility lane representation was selected. A positive-index
left-lane alternative reversed all479 road directions in a SUMO reimport check
and was excluded from this delivery. Vissim's left-hand-traffic setting and every
imported lane/connector direction still require native inspection; a successful
SUMO check cannot establish Vissim behavior.

Signal and controller placeholders were removed intentionally. The raw exporter
emitted repeated IDs for joined controllers. Geometry transfer does not recreate
AmbuGo's adaptive control, signal timings, requests, demand or vehicle behavior.
PTV's documented OpenDRIVE importer can synthesize basic fixed-time signal plans;
these must not be mistaken for the original controller. Rebuild and validate the
actual signal/controller logic separately using the provided scenario references.

VALIDATION COMPLETED
- XML parses successfully; road and junction IDs are unique.
- All479 source regular-road IDs and556 regular lanes are represented.
- Structural checks found 12 dangling predecessor references. All referred to
  source dead-end boundaries with no incoming connection. These invalid references
  were removed with tools/repair_boundary_refs.py. Geometry and lanes are unchanged;
  no valid connection was removed. The final file has no missing road/junction
  references. Details are in boundary_repair.json and validation.json.
- SUMO can reimport the candidate; its479 regular roads retain endpoint direction
  under the left-hand diagnostic.
- The original source network hash is unchanged.

MATERIAL LIMITATIONS
- No OpenDRIVE XSD validation or native Vissim validation has been completed.
- Structural reference checks now pass, but this remains a transfer candidate
  requiring native validation, not a validated Vissim network.
- Export reports five uneven stop lines that cannot be represented exactly,
  unsmoothed connectors, sharp turns and intersecting turning paths. Full warnings
  are included. The source geometry was not silently changed to hide warnings.
- The diagnostic SUMO reimport preserves counts and direction but is not
  geometrically identical. Mean per-road average lane0 endpoint difference is
  4.71m; the maximum is12.70m. These measure export plus SUMO reconstruction, not
  a Vissim error estimate. Native geometry and stop-line review are required.
- Lane widths/speeds and signal settings include synthetic assumptions. The local
  Fortis roundabout correction is imagery-derived, not surveyed ground truth.
- No deployment, field accuracy or cross-simulator equivalence is established.

GEOREFERENCING
The coordinate system is WGS84 / UTM43N (EPSG32643). Geometry uses local meters;
UTM Easting=local_x+661613.76, Northing=local_y+3394640.60. OpenDRIVE stores this
translation in header/offset, and its projection in header/geoReference.
georeferencing.json supplies landmark control points. Verify the native importer
applies the translation once and aligns the hospital, PCL junction and roundabout.

REPAIR REPRODUCTION
The bundled source_mohali.net.xml is the unchanged source network. The export
options are in export_manifest.json. After export and removal of signal/controller
placeholders, run tools/repair_boundary_refs.py with the source network, input
OpenDRIVE, output OpenDRIVE and a JSON report path. The script refuses repairs
unless source topology proves the dangling predecessor is an unconnected boundary.

Independent mathematical and implementation audit of the v9 SUMO extension
25 October 2026

Scope
Read-only audit of work/v9/sumo_study.py plus sumo_notes.txt and pilot diagnostics. The initial reviewed source hash was5eb2d7cb906fefcb3f5bd082f5c94056e22b5707d7e2647a997156469b51dd3a. The implementation agent repaired the two concrete issues reported during this audit. The final reviewed source hash is44cedf73590afaef3bf7cf3350b78e5736e33a120309db506d111af93065de30. No source files were edited by this reviewer and no new global experiment was run. The final findings below supersede the initial defect reports.

Overall assessment
The ordinary-vehicle population accounting is substantially stronger than v8. The exhaustive fixed partition, unique ordinary-versus-ambulance distinction, desired-release source queues, actual simulator completion clocks and independent vehicle residence sum support the intended finite-horizon residence identity. The code is an executable heuristic route-and-priority controller with a finite action/route screening calculation. It is not CCR, not an exhaustive microscopic optimizer and not a model-certified near-optimal city route. Its congestion score and nominal saturation labels are analytical proxies rather than guarantees.

Resolved implementation defects and final band guarantee
The initial source applied the rolling ETA trigger before forwarding an existing P3 lease and allowed route-switch hysteresis to override the initial global surrogate time cap. Both defects were reported to the implementation agent and parent and are repaired in the final reviewed source. Existing leases now bypass the fresh-request trigger gate. The legal incumbent route is included among at most4 candidate continuations, and every candidate selected by the hysteresis branch is filtered against the same global minimum-predicted-time-plus-epsilon cap. A runtime assertion checks the final selected predicted time and logs the global minimum.

Proposition. For a nonempty frozen list of finite candidate predicted values, the final P3 plan returned by the current implementation has predicted time no greater than the minimum over that list plus epsilon, up to its declared floating-point assertion tolerance.
Proof. The initial minimization is restricted to that eligible list. The only subsequent replacement is an incumbent-route value from vv, which is explicitly filtered by the same global cap. The final assertion rejects any remaining cap violation. This proves a property of the computed surrogate values on this one decision snapshot, not a true travel-time guarantee.

An important qualification remains: the route hysteresis can retain an eligible incumbent with a higher surrogate harm value than the initial global harm-minimizing candidate. Thus final selection is a global-time-band-respecting harm preference with route hysteresis; it is not always the global lexicographic minimum of surrogate harm over all eligible route-action pairs. Do not claim the latter without including hysteresis explicitly in the optimization formulation. No realized-ambulance or real-world near-optimality guarantee follows.

What is actually optimized
At each regular edge entry, the controller considers up to four loopless continuation routes within a free-flow path ratio of1.5, prepending the current edge and retaining a legal incumbent continuation in that pool. P3 action_mode multi uses none,(10,20),(20,40),(30,60), while action_mode strong uses none,(30,60). Routes are bounded using public free-flow times, not the exact microscopic controlled travel times. The selected pair applies a deterministic approximate forecast and a time-band-respecting harm preference with route hysteresis, conditional on delayed/noisy current counts and current signal states. Future nominal signal continuation is projected, but later priority switching is approximated from current switch delay and does not simulate the future controlled state along the candidate route. Several requests on a route are assessed independently and their surrogate burdens added. These are explicit approximations, so call the result finite-candidate joint heuristic selection rather than exact control optimization or global route optimality.

P1 chooses a traffic-aware route under nominal-signal estimates and only subsequently requests unconditional priority. P2 anticipates priority in route scoring but uses one fixed aggressive action. P3 adds the action library and selective gates. The P3-versus-P2 comparison therefore bundles selectivity with action-library differences and lexicographic harm preference; it is not an isolated causal estimate of only one scalar burden gate. P0 itself reroutes dynamically using traffic-aware estimates, which is a reasonable strong route-only baseline, but is different from a fixed free-flow ambulance route.

The pulse burden is a ranking surrogate
pulse() computes, for other approaches at the next junction, qhat*D + lambda*D^2/[2max(1-X,.05)], where qhat is max(0,delayed observed link count minus mean ordinary inflow times free-flow time), D is a capped expected lost-green exposure, lambda is nominal vehicle flow and X is the assumed design saturation proxy. Units are vehicle-seconds. The derivation from an isolated empty-baseline fluid queue motivates the inverse-slack term; it is not a conservative bound on network residence or the positive spatial aftereffect measure A. It does not model receiving-space propagation, observer dynamics, future demand, shared downstream capacity or microscopic heterogeneous service exactly.

The public harm_budget is a PER-LOCAL-PULSE admission threshold. There is no accumulated citywide, mission or episode aftereffect budget, no shadow-baseline state used by the controller, and no hard constraint that actual A_H or Delta J_H stays below that number. The persistent paired baseline is an evaluation device. A paper claiming that the implemented controller enforces an actual global congestion budget would be false. P3 reduces the surrogate harm within its candidate band and rejects some locally expensive requests; its effectiveness must be assessed in held-out actual trajectories.

The receiving-headroom test compares the delayed all-vehicle count on the next regular edge with .85 times a coarse count-storage value from the CSV. It does not reserve space for the proposed discharge pulse and is not a physical guarantee that the pulse or ambulance fits. The actual SUMO receiving/lane dynamics enforce physical insertion and can block the maneuver. The pulse crossing check uses a queue-clearance proxy and a two-second start-up allowance; actual ambulance queue position and future signal contention remain uncertain. These checks are filtering heuristics, not safety or feasibility certificates.

Leases, simultaneous missions and guards
The code stores at most one lease per ambulance/incoming edge. It initializes its expiry from the first observed matching actual green, measured relative to that green's elapsed age, caps pending duration at120 s, and does not allow renewal on the same edge after finished_leases is set. A headroom rejection or service-age guard can prevent the intended pulse. A lease has no recursive-feasibility or ambulance-arrival guarantee. If a guard interrupts its green, the wall-clock expiry remains fixed; it is not an accumulated actual-green service account.

Conflicting requests are arbitrated by earliest desired dispatch time, with ambulance ID as tie-break, not by earliest predicted arrival or estimated clinical urgency. All active ambulances are subject to that deterministic ordering. The code can create/store a tentative lease before checking whether an earlier ambulance has already won the same junction tick, so lease bookkeeping is not identical to successful priority-phase admission. Report actual signal admissions, request ticks and expiration counts with their distinct definitions.

Eight-second minimum green, three-second amber, two-second all-red and a25 s all-red pedestrian opportunity are represented by a concrete automaton. Completed phase spans are audited, while a final unfinished span is not a completed interval. The alternative base controller is longest-queue, not classic or capacity-aware max-pressure. The150 s guard tracks demanded service age and the synthetic pedestrian opportunity age; it is not an individual queued-vehicle waiting bound or a proof of feasibility. No physical pedestrian agents, walking paths, real pedestrian demand or clinical urgency model is represented.

Ordinary population census and residence proof
At each simulator substep, regular edge subscriptions supply all live vehicle counts, regular-edge ambulances are subtracted, and one INTERNAL bucket accounts for ordinary live vehicles on connector edges. The eight SOURCE buckets equal the number of ordinary desired departures by the current simulator time minus insertions observed so far. Their sum is asserted equal to desiredreleased minus ordinarycompleted at every substep; a negative bucket raises an error. This fixed68-group partition is exhaustive for the modeled ordinary population.

The ordinary residence sum uses the left-endpoint population over each physical step. All desired releases lie on the integer-second grid and substeps .5/.25 divide that grid; actual completion event clocks use the simulator's time at step completion. A separate ordinary-by-ordinary sum of [min(exit,H)-max(desired,warmup)]_+ is compared to the count integral, with an exception on error. This implements the finite-horizon accounting identity under the recorded simulator clocks; no stationarity or Little's-law invocation is required. It includes ordinary source waiting and unfinished ordinary travel and excludes ambulance occupancy. The pilot file reports zero identities at both .5 and.25 s for its four cases; that is useful implementation evidence, not an exhaustive proof that every possible runtime input is valid.

Positive spatial burden can be computed exactly relative to the recorded grid trajectories as dt*sum(max(counts_pi-counts_P0,0)) over the same fixed partition. Consequently Delta J=A-B and A>=max(Delta J,0) can be verified algebraically. Grouping all internal connectors together loses internal spatial resolution and yields a coarser burden than separating them, while keeping the residence identity exact. Counts use int16 traces; current synthetic magnitudes are small enough, but a generic city-scale claim would require overflow checks or a wider storage type.

Ambulance clocks and censoring
Ambulance travel is actual recorded arrival minus desired dispatch; source insertion delay is included implicitly. A desired-but-uninserted ambulance is retained in the mission ledger and is censored. The code's restricted duration is H-dispatch when censored: it uses the common absolute experiment end, not one common fixed L-second deadline for every mission. If the paper defines a fixed restricted horizon such as600 s per mission, that metric must be computed explicitly during analysis. Report nonarrival and any deadline exceedance separately. All methods share the same desired mission schedule and end time, so paired episode comparisons remain well-defined.

The field insertion_observed uses the simulator-step event receipt time. It is explicitly labeled observed rather than an independently reconstructed substep continuous insertion event, which is appropriate. Do not change that label to exact physical insertion time without checking SUMO's departure timestamp semantics.

Causality and stochastic scope
The runner passes only the scenario seed and public design to Controller, rather than the future departure schedule. Requests receive only currently active ambulance dictionaries. The controller has delayed count observations and current signal states; it does not read the evaluation baseline or future ordinary arrivals. The seed is used for sensor draws rather than looking up future demand. Technically the controller holds a full model specification and could reconstruct seeded plant inputs, but no such reconstruction is implemented.

Primary sensors refresh every5 s, have2 s receipt delay, bounded noise and independent-by-link Markov availability. The zero-delay sensitivity immediately assimilates samples in the same observation call. Observation ages are stored but not used for uncertainty inflation, stale-data fallback or a Bayesian update. The network counts include ambulances before the queue proxy is formed, matching an unlabeled aggregate detector rather than an ordinary-only queue measurement. There is no clustered outage, incident, yielding device, continuous sublane filtering or physical pedestrian model in this SUMO extension. Its primary physical model uses sigma0 and deterministic speed factors, with heterogeneity in dimensions/headways/acceleration and stochastic demand/class/route draws.

Nominal target load is an EX ANTE PCU design proxy. The CSV saturation flows are assumptions and are not independently fitted to achieved SUMO discharge. signal_design computes its reported X with unrounded allocated greens but executes rounded integer greens; therefore the reported nominal X can differ slightly from the corresponding rounded-plan proxy. It should never be called measured SUMO critical saturation. Arrival rates share a stationary-initialized AR(1) lognormal shock with mean correction, while desired event times are quantized upward. Initial warmup is not demonstrated stationarity; source queues and occupancy trajectories must be checked rather than assumed stationary.

Minimum paper wording
The defensible algorithm claim is 'a causal finite-candidate joint route-and-selective-priority heuristic with bounded signal requests and a local queue-inspired burden surrogate, evaluated in synthetic SUMO traffic.' Its computed surrogate-time-band guarantee, physical signal legality, exact ordinary accounting and empirical traffic effects are four distinct claims. The current code can support the latter two through proofs plus checks and the empirical comparison through archived simulations. It does not prove global ambulance optimality, a real-city accuracy guarantee, a hard aftereffect budget or real-world safety.
